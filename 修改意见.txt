这是一个非常关键的业务闭环补充！之前的设计中，管理员发布的更多是“通知公告（Notice）”，而你现在需要的是一个**具有业务属性的“申报批次（Batch）”**。

这就好比：通知是“请大家注意”，而批次是“请大家在2025-12-31前把材料交到这里”。**批次是具有生命周期（开始时间、截止时间、状态）的实体对象**。

为了实现这个“发布即生效，教师可见”的功能，我们需要对**管理员端的发布组件**进行功能升级，并明确后端的数据流转。

---

### 🏛️ 业务逻辑架构图

1. **管理员操作**：填写批次名称、设置截止日期 -> 点击发布 -> 后端写入 `project_batches` 表。
2. **数据流转**：该记录携带 `dept_id`（学院）和 `status=1`（开放中）。
3. **教师端响应**：教师进入申报页 -> 自动请求 `GET /batches` -> 后端根据教师 `dept_id` 过滤 -> 前端下拉框出现新批次。

### 🔗 2. 后端联动逻辑 (Server Logic)

为了让上述前端按钮生效，并在教师端体现，后端需要执行以下逻辑：

#### A. 数据库表结构确认 (`project_batches`)

确保你的数据库有这张表，并且包含 `status` 和 `dept_id`。

```sql
CREATE TABLE project_batches (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(255) NOT NULL,          -- 批次名称
    description TEXT,                    -- 批次描述/要求
    deadline DATETIME NOT NULL,          -- 截止时间
    dept_id BIGINT NOT NULL,             -- 【核心】所属学院ID
    publisher_id BIGINT NOT NULL,        -- 发布人ID
    status INT DEFAULT 1,                -- 1: 开放, 0: 关闭
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

```

#### B. 教师端获取批次的 API (`GET /api/batches/available`)

当教师打开“项目申报”页面时，前端会自动请求这个接口。后端必须做以下处理：

1. **获取当前用户身份**：解析 Token，拿到 `current_teacher_id` 和 `current_teacher_dept_id`（例如：计算机学院）。
2. **执行查询**：
```sql
SELECT * FROM project_batches 
WHERE status = 1 
AND deadline > NOW() 
AND dept_id = {current_teacher_dept_id}; -- 【关键】只查本学院

```


3. **返回数据**：前端 `ProjectApplyForm.tsx` 接收到数据后，渲染下拉框。

### ✅ 总结

这次修改主要是在 **“管理员端”** 增加了一个**正规的表单**来生产数据。

* **以前**：发布通知可能只是发个文本公告，不产生业务关联。
* **现在**：发布的是一个 **Structued Object (结构化对象)**，它包含 `deadline` 和 `dept_id`，这正是系统能够自动控制“谁能申报”、“何时截止”的关键数据源。

              <AlertTriangle className={`w-4 h-4 mr-2 ${priority === 'high' ? 'text-orange-600' : 'text-slate-400'}`} /> 
              重要程度
            </h3>
            <div className="flex bg-white/50 p-1 rounded-xl border border-slate-200/50">
              <button onClick={() => setPriority('normal')} className={`flex-1 py-2 text-xs font-bold rounded-lg transition-all ${priority === 'normal' ? 'bg-white shadow-sm text-slate-700' : 'text-slate-400 hover:text-slate-600'}`}>普通批次</button>
              <button onClick={() => setPriority('high')} className={`flex-1 py-2 text-xs font-bold rounded-lg transition-all flex items-center justify-center ${priority === 'high' ? 'bg-orange-500 text-white shadow-md shadow-orange-200' : 'text-slate-400 hover:text-orange-600'}`}>紧急通知</button>
            </div>
          </div>

          {/* 3. 提交按钮 */}
          <button
            onClick={handlePublish}
            disabled={isSending}
            className={`w-full py-4 rounded-xl font-bold text-white shadow-xl flex items-center justify-center transition-all active:scale-95 duration-300 ${
              isSending 
                ? 'bg-slate-400 cursor-not-allowed' 
                : 'bg-gradient-to-r from-indigo-600 to-blue-600 shadow-indigo-500/30 hover:shadow-indigo-500/50'
            }`}
          >
            {isSending ? (
              <>
                <RefreshCw className="w-5 h-5 mr-2 animate-spin" />
                正在创建批次...
              </>
            ) : (
              <>
                <Save className="w-5 h-5 mr-2" />
                确认发布申报
              </>
            )}
          </button>
          <p className="text-center text-xs text-slate-400">
            发布后将立即出现在本院教师的申报列表中。
          </p>

        </div>
      </div>
    </div>
  );
};

```

### 🔗 2. 后端联动逻辑 (Server Logic)

为了让上述前端按钮生效，并在教师端体现，后端需要执行以下逻辑：

#### A. 数据库表结构确认 (`project_batches`)

确保你的数据库有这张表，并且包含 `status` 和 `dept_id`。

```sql
CREATE TABLE project_batches (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(255) NOT NULL,          -- 批次名称
    description TEXT,                    -- 批次描述/要求
    deadline DATETIME NOT NULL,          -- 截止时间
    dept_id BIGINT NOT NULL,             -- 【核心】所属学院ID
    publisher_id BIGINT NOT NULL,        -- 发布人ID
    status INT DEFAULT 1,                -- 1: 开放, 0: 关闭
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

```

#### B. 教师端获取批次的 API (`GET /api/batches/available`)

当教师打开“项目申报”页面时，前端会自动请求这个接口。后端必须做以下处理：

1. **获取当前用户身份**：解析 Token，拿到 `current_teacher_id` 和 `current_teacher_dept_id`（例如：计算机学院）。
2. **执行查询**：
```sql
SELECT * FROM project_batches 
WHERE status = 1 
AND deadline > NOW() 
AND dept_id = {current_teacher_dept_id}; -- 【关键】只查本学院

```


3. **返回数据**：前端 `ProjectApplyForm.tsx` 接收到数据后，渲染下拉框。

### ✅ 总结

这次修改主要是在 **“管理员端”** 增加了一个**正规的表单**来生产数据。

* **以前**：发布通知可能只是发个文本公告，不产生业务关联。
* **现在**：发布的是一个 **Structued Object (结构化对象)**，它包含 `deadline` 和 `dept_id`，这正是系统能够自动控制“谁能申报”、“何时截止”的关键数据源。
